# Facilitator answer key

Expected discovery themes include: a regional publication lead-time branch in `Notice.PublicationDate`; emergency timing bypass; create/edit validation differences; exact-title duplicate detection; case/whitespace inconsistency in search; approval without an audit entry; rejected-state rules; local-date defaults; and differences between baseline prose and code.

Useful characterisation scenarios include equal effective/expiry dates, high severity with missing description, empty emergency explanation, repeated titles with case or surrounding whitespace differences, approval audit history, export from a non-approved state, and a stale edit. A test that confirms existing behaviour is not approval of that behaviour. Ask which source establishes policy.

Accept an amended or rejected generated suggestion if the participant cites evidence and identifies what needs confirmation. Do not accept mass assertions or unverified requirement claims just to increase test count.
